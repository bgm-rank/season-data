# 重构方案设计

## 一、动机

当前设计存在两个耦合问题：

1. **命令割裂**：编辑 `manual/` 后用 `complete`，改 `override/` 后用 `run`，用户需要记住不同场景对应不同命令
2. **状态语义混乱**：8 个状态把"决策结果"和"决策来源"混在一起，难以理解和扩展
3. **无可视化**：所有操作依赖 CLI + 手动编辑 JSON，审核体验差

## 二、用户故事

### Epic A：季度管理

- **US-A1**：作为用户，我可以在首页看到所有季度的列表，每行显示状态摘要（已收录数 / 待审核数 / 总数），并可进入某个季度的详情页
- **US-A2**：作为用户，我可以创建一个新季度任务（选年份 + 季节）

### Epic B：数据获取

- **US-B1**：作为用户，我可以点击"拉取 MAL 数据"，系统从 MAL API 获取该季度的完整番组清单并存储，完成后显示条目总数

### Epic C：匹配运行

- **US-C1**：作为用户，我可以点击"运行匹配"，系统依次执行 rule → exact → LLM 三层策略，并实时显示进度（已处理 N/总数，当前状态分布）
- **US-C2**：作为用户，我可以点击"强制重跑"，对已处于 pending 状态的条目重新调用 LLM

### Epic D：结果审核

- **US-D1（有候选）**：对于 LLM 给出了候选但置信度低于阈值的条目，我可以看到左侧 MAL 信息和右侧候选列表，点击一个候选确认收录，或点击"跳过"排除
- **US-D2（无候选）**：对于完全未匹配的条目，我可以通过搜索框搜索 Bangumi 标题，从结果中选择收录；或标记为跳过

### Epic E：Override 管理

- **US-E1**：作为用户，我可以将某条 MAL 条目加入"强制跳过"列表，用于排除 MAL 中多余或标错季度的番组
- **US-E2**：作为用户，我可以将某个 Bangumi 条目强制加入该季度，用于补录 MAL 遗漏的番组

### Epic F：导出

- **US-F1（Release 导出）**：作为用户，我可以一键生成 release JSON，仅包含 `status=included` 的条目，按 bgm_id 排序
- **US-F2（完整快照导出）**：作为用户，我可以导出该季度的完整状态快照（含 pending/excluded 及原因），用于跨机器迁移或灾难恢复

## 三、整体流程

```
首页（季度列表）
  ├─ 新建季度 → 选年份/季节
  └─ 进入某季度 → 季度详情页
       ├─ [拉取 MAL]      → 获取原始数据
       ├─ [运行匹配]      → rule + exact + LLM（含置信度）
       ├─ [审核队列]      → pending 条目，分两种交互:
       │    ├─ 有候选: 展示候选列表 → 点选 or 跳过
       │    └─ 无候选: 搜索 BGM → 选择 or 跳过
       ├─ [Override 管理] → 强制跳过 / 强制添加
       ├─ [导出 Release]  → 生成 release JSON
       └─ [导出快照]      → 完整状态备份

季度状态机:
  INIT → [US-B1] → FETCHED → [US-C1] → MATCHED → [US-D/E] → REVIEWING → [US-F1] → RELEASED
  任意状态下可执行: US-E1/E2（触发幂等重跑）、US-F2（导出快照，不改变状态）
```

## 五、状态重设计

### 新设计：正交分离

#### `status`（决策结果）— 只有 3 个值

| 值 | 含义 |
|----|------|
| `pending` | 待人工决定 |
| `included` | 收录进 release |
| `excluded` | 不收录 |

#### `source`（决策来源）— 元数据字段

| 值 | 含义 |
|----|------|
| `rule` | 媒体类型规则自动排除（special/pv/cm 等） |
| `exact` | 日文标题精确匹配 |
| `llm` | LLM 匹配（置信度 ≥ 阈值） |
| `human` | 人工决定 |

`source` 为 `null` 表示该条目尚未经过匹配流程（新条目入队时的初始状态）。

#### LLM 置信度阈值

LLM 在返回候选时同时输出 `confidence: 0.0~1.0`：

- `confidence ≥ 阈值`（默认 `0.85`）→ `included / llm`，自动收录
- `confidence < 阈值` → `pending / llm`，进入审核队列，candidates 列表保留供人工选择
- 无候选 → `pending / llm`，需手动搜索 BGM

阈值作为配置项，可在 UI 中调整。

#### 旧状态映射

| 旧状态 | 新 status | 新 source |
|--------|-----------|-----------|
| `SKIP` | `excluded` | `rule` |
| `MATCH` | `included` | `exact` |
| `MODEL` | `included` | `llm` |
| `MODEL_SKIP` | `excluded` | `llm` |
| `HUMAN` | `included` | `human` |
| `HUMAN_SKIP` | `excluded` | `human` |
| `UNCONFIRMED` | `pending` | `null` |
| `ERROR` | `pending` | `null`（附 `error` 字段记录原因） |

## 六、存储层：SQLite

### git 追踪策略

```
追踪（提交到 git）               不追踪（.gitignore）
────────────────────────         ────────────────────────
release/*.json  ← 发布产物        season.db  ← 工作状态
data/mal/*.json ← 原始数据
```

`override/` JSON 文件完全迁移进 `overrides` 表，不再保留文件。

### Schema 设计

```sql
CREATE TABLE seasons (
    id          TEXT    PRIMARY KEY,  -- "2025-spring"
    year        INTEGER NOT NULL,
    season      TEXT    NOT NULL,     -- winter/spring/summer/fall
    status      TEXT    NOT NULL,     -- init/fetched/matched/reviewing/released
    created_at  TEXT    NOT NULL,
    updated_at  TEXT    NOT NULL
);

CREATE TABLE items (
    mal_id          INTEGER NOT NULL,
    season_id       TEXT    NOT NULL,
    status          TEXT    NOT NULL,   -- pending / included / excluded
    source          TEXT,               -- rule / exact / llm / human / null
    confidence      REAL,               -- LLM 输出的置信度（仅 source=llm 时有值）
    bgm_id          INTEGER,
    bgm_name        TEXT,
    bgm_name_cn     TEXT,
    mal_title       TEXT,
    mal_title_ja    TEXT,
    mal_media_type  TEXT,
    mal_rating      TEXT,
    error           TEXT,               -- 匹配失败原因（仅 pending 时有值）
    candidates      TEXT,               -- JSON 数组，候选列表
    updated_at      TEXT,
    PRIMARY KEY (mal_id, season_id),
    FOREIGN KEY (season_id) REFERENCES seasons(id)
);

CREATE TABLE overrides (
    mal_id      INTEGER NOT NULL,
    season_id   TEXT    NOT NULL,
    action      TEXT    NOT NULL,       -- add / skip
    bgm_id      INTEGER,                -- action=add 时必填
    PRIMARY KEY (mal_id, season_id),
    FOREIGN KEY (season_id) REFERENCES seasons(id)
);
```

### 常用查询

| 操作 | SQL |
|------|-----|
| release 生成 | `SELECT * FROM items WHERE season_id=? AND status='included' ORDER BY bgm_id` |
| 审核队列 | `SELECT * FROM items WHERE season_id=? AND status='pending' ORDER BY confidence ASC` |
| 人工确认 | `UPDATE items SET status='included', source='human', bgm_id=? WHERE mal_id=? AND season_id=?` |
| 人工跳过 | `UPDATE items SET status='excluded', source='human' WHERE mal_id=? AND season_id=?` |
| 季度摘要 | `SELECT status, COUNT(*) FROM items WHERE season_id=? GROUP BY status` |

## 七、后端 API 设计

```
GET    /api/seasons                      # 季度列表（含摘要统计）
POST   /api/seasons                      # 新建季度
GET    /api/seasons/{id}                 # 季度详情

POST   /api/seasons/{id}/fetch           # 拉取 MAL 数据
POST   /api/seasons/{id}/run             # 启动匹配任务，返回 task_id
GET    /api/seasons/{id}/run/progress    # SSE 实时进度流
POST   /api/seasons/{id}/run?retry=true  # 强制重跑 pending

GET    /api/seasons/{id}/items           # 条目列表（可按 status/source 过滤）
PATCH  /api/seasons/{id}/items/{mal_id}  # 更新条目（人工确认/跳过）

GET    /api/seasons/{id}/overrides       # Override 列表
POST   /api/seasons/{id}/overrides       # 添加 override
DELETE /api/seasons/{id}/overrides/{mal_id}

GET    /api/seasons/{id}/release         # 预览 release 内容
POST   /api/seasons/{id}/export/release  # 导出 release JSON 文件
POST   /api/seasons/{id}/export/snapshot # 导出完整快照

GET    /api/bgm/search?q=&season=        # Bangumi 搜索代理
```

## 八、命令行（保留，供自动化使用）

| 命令 | 作用 |
|------|------|
| `run <year> <season>` | 处理季度（幂等） |
| `run --retry <year> <season>` | 强制对 pending 条目重跑 LLM |
| `release <year> <season>` | 从现有 state 生成 release，不调用 API |
| `export <year> <season>` | 导出完整快照 JSON |

`complete` 命令删除（由 `run` 的幂等逻辑覆盖）。

### `run` 的幂等逻辑

```
1. override.skip 列表中？            → excluded / rule，跳过后续
2. 已有 status=included/excluded？  → 直接复用（human 来源重新拉取 bgm 名称）
3. 有 bgm_id 但无 bgm_name？        → 拉取名称，status=included，source=human
4. status=pending 且 source≠null？  → 已处理过但未匹配，保留（不重跑 LLM）
5. 否则（新条目 或 --retry 模式）   → 执行完整匹配流程
```
